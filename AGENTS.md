# Project instructions for LLM agents

## Harness dependency

Before substantive work, read `harness-adoption.yaml`, then load the pinned
`scientific-research-harness/HARNESS.md` contract at the exact immutable ref declared
there.

If the pinned contract is unavailable, state the limitation. Orientation and
non-outcome-bearing diagnostics may continue, but do not claim harness compliance, alter a
scientific gate, or present new outcome-bearing work as admissible evidence.

## Authority

The harness constrains method; it does not replace source papers, frozen protocols,
executable evidence, researchers, teachers or domain expertise. Keep domain-specific
claims and explanations in this repository and link them to their authoritative artifacts.

## Thread startup

At the start of each new project thread, make the following state recoverable before
substantive action:

- pinned harness ref and local manifest;
- task identifier and intended bounded action;
- authoritative sources;
- current scientific gates and unresolved blockers;
- missing context that prevents a compliant claim.

## Required working boundary

Preserve the distinction between evidence, Chronicle decisions and pedagogy. Never release
a scientific gate with an understanding check, benchmark, prose explanation or incomplete
result. Randomness and concurrency changes must preserve task-bound seed lineages and the
declared serial/reference equivalence relation.

Before handoff, record reproducible commands, frozen artifacts, evidence produced,
unresolved gates and the exact next admissible action.
